1.2 Server Provisioning

1Create Server User

curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -

sudo npm install -g pm2

3Clone Repository

su - paylinkssh

cd /home/paylinkssh/paylink-app
git clone git@github.com:YOUR-ORG/PayLink.git
cd PayLink

1.3 PostgreSQL Database Setup

1Install PostgreSQL

sudo apt install postgresql postgresql-contrib
sudo systemctl enable postgresql

2Create Database & User

sudo -u postgres psql
CREATE USER apppaylinkmain WITH PASSWORD 'YOUR_SECURE_PASSWORD';
CREATE DATABASE apppaylinkmain OWNER apppaylinkmain;
GRANT ALL PRIVILEGES ON DATABASE apppaylinkmain TO apppaylinkmain;
\q
Security Warning Never commit database passwords to source control. Use environment variables or GitHub Secrets exclusively.

1.4 Application Deployment

1Configure Environment

Create /home/paylinkssh/paylink-app/PayLink/.env:

DATABASE_URL=postgresql://apppaylinkmain:PASSWORD@127.0.0.1:5432/apppaylinkmain
SESSION_SECRET=your-random-64-char-secret
NODE_ENV=production
HOST=127.0.0.1
PORT=8000
APP_BASE_URL=https://mypaylink.app
UPLOAD_DIR=/home/paylinkssh/paylink-app/PayLink/uploads

2Build & Start

cd /home/paylinkssh/paylink-app/PayLink
npm install --production=false
npm run build
cp node_modules/connect-pg-simple/table.sql dist/
pm2 start "node -r dotenv/config dist/index.cjs" --name paylink
pm2 save
pm2 startup

3Verify

curl http://127.0.0.1:8000/health   # Should return 200
curl http://127.0.0.1:8000/ready    # Should return 200 (DB connected)

1.5 Nginx Reverse Proxy & SSL

1Install Nginx & Certbot

sudo apt install nginx certbot python3-certbot-nginx

2Configure Nginx

Create /etc/nginx/sites-available/paylink-app:

server {
    listen 80;
    server_name mypaylink.app;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        client_max_body_size 50M;
    }
}

# Enable and get SSL
# sudo ln -s /etc/nginx/sites-available/paylink-app /etc/nginx/sites-enabled/
# sudo certbot --nginx -d mypaylink.app

1.8 GitHub Actions CI/CD

The deployment workflow at .github/workflows/deploy.yml automates:

  1. Database backup (using DB_PASSWORD secret)
  2. Git pull latest code
  3. Install dependencies
  4. Build application
  5. Copy session table SQL
  6. Restart with PM2
  7. Health check verification
  8. Old backup cleanup (keeps last 10)

Required GitHub Secrets:

Secret NameDescription

VPS_USERSSH username (paylinkssh)
VPS_SSH_KEYPrivate SSH key for deployment
DB_PASSWORDPostgreSQL password for backups

1.9 Backup & Recovery

Automated Backups

Set up a cron job for daily backups:

# Edit crontab
crontab -e

# Add daily backup at 2 AM
0 2 * * * PGPASSWORD='$DB_PASSWORD' pg_dump -U apppaylinkmain -h 127.0.0.1 apppaylinkmain > /home/paylinkssh/backups/paylink_$(date +\%Y\%m\%d).sql

# Keep only last 30 days
0 3 * * * find /home/paylinkssh/backups -name "*.sql" -mtime +30 -delete

Manual Recovery

psql -U apppaylinkmain -h 127.0.0.1 apppaylinkmain < /home/paylinkssh/backups/paylink_YYYYMMDD.sql

1.10 Monitoring & Maintenance

  • Monitor /health and /ready endpoints with uptime service (UptimeRobot, etc.)
  • Review PM2 logs weekly for errors: pm2 logs paylink --lines 500 --nostream | grep -i error
  • Monitor disk usage: df -h (especially uploads directory)
  • Update Node.js and system packages monthly
  • Rotate SSL certificates (Certbot auto-renews)

1.11 Security Hardening

  • Firewall: Only ports 22, 80, 443 open (UFW)
  • SSH: Key-only auth, no root login
  • Database: Listen on localhost only (127.0.0.1)
  • App: Binds to 127.0.0.1, served via Nginx proxy
  • Secrets: Never in code — env vars and GitHub Secrets only
  • HSTS, X-Content-Type-Options, X-Frame-Options headers enabled
  • Session cookies: httpOnly, secure, sameSite=lax
  • Regular dependency audits: npm audit
Customer Company — Onboarding

Part 2: Implementation Guide

Setting up PayLink for a new customer organization

2.1 Pre-Implementation Checklist

Gather the following before beginning setup:

  • Company legal name, DBA, EIN (Federal Tax ID)
  • State tax ID numbers (e.g., California EDD number)
  • Company address, phone, and primary contact
  • Bank account information for payroll (routing + account number)
  • Employee roster with: names, SSNs, addresses, pay rates, hire dates
  • Department and branch structure
  • Pay schedule (weekly, bi-weekly, semi-monthly, monthly)
  • Existing PTO/accrual balances to carry over
  • Current tax withholding elections (W-4 data)
  • Workers' compensation classification codes
  • List of job codes / positions
  • Direct deposit enrollment forms

2.2 Enterprise & Company Setup

1Create Enterprise (if new)

An enterprise is the top-level entity (e.g., "Alavont Holdings") that contains one or more companies. If the customer is joining an existing enterprise, skip this step.

2Create Company

  1. Navigate to Companies in the sidebar
  2. Click Add Company
  3. Enter: Legal Name, DBA, EIN, address, phone
  4. Assign to the enterprise
  5. Set pay period schedule
  6. Save

3Configure Remittance Source

Required for ACH direct deposit:

  1. Go to the company's settings
  2. Add Remittance Source with bank routing number, account number, and company name
  3. This is the source bank account for all direct deposit payments

2.3 Organizational Structure

Set up the following in order:

EntityDescriptionExample
BranchesPhysical locationsMain Office, Warehouse
DepartmentsFunctional areasEngineering, Sales, Admin
DivisionsBusiness divisionsWest Coast, East Coast
PositionsJob rolesManager, Technician
JobsJob codes for cost trackingJOB-001, JOB-002
Cost CentersBudget allocation centersCC-100, CC-200
Universal Entities Divisions, Cost Centers, and Secondary Wage Groups with no company assigned are available to ALL companies in the enterprise. Assign a specific company to restrict access.

2.4 Employee Data Import

Option A: CSV Import

  1. Prepare a CSV file with columns: firstName, lastName, email, phone, payRate, payType, hireDate, employeeNumber, department, workerType
  2. Navigate to the company, then use the CSV import function
  3. Map columns to PayLink fields
  4. Review and confirm the import

Option B: Manual Entry

  1. Go to Employees → Add Employee
  2. Fill in all required fields
  3. Set worker type (Employee or Contractor) and worker group
  4. Enter pay rate and pay type (hourly/salary)
  5. Save

Post-Import Steps

  • Assign departments, branches, and positions to each employee
  • Enter SSNs for tax reporting (encrypted at rest)
  • Set up direct deposit bank info for applicable employees
  • Create employee PINs for time clock access
  • Upload any required documents (I-9, W-4, etc.)

2.5 Payroll Configuration

1Tax Setup

  1. Navigate to the company's tax configuration
  2. Enter Federal EIN
  3. Enter State tax IDs
  4. Configure withholding rates (Federal, State, FICA, Medicare)
  5. Set up any additional local taxes

2Deduction Templates

Create standard deductions:

  • Health insurance (pre-tax)
  • 401(k) / retirement (pre-tax)
  • Dental / Vision (pre-tax)
  • Garnishments (post-tax)
  • Union dues (post-tax)

2.6 Time & Attendance Setup

  1. Stations: Create time clock stations for each physical location
  2. Overtime Rules: Configure daily OT (California: 8h daily, 12h double-time) or weekly OT
  3. Rounding: Set punch rounding rules if applicable
  4. Break Policies: Configure meal and rest break tracking
  5. Accruals: Set up PTO, sick, and vacation accrual policies

2.7 User Accounts & Role Assignment

Create Admin Accounts

  1. Navigate to Settings → Users
  2. Create accounts for company managers
  3. Assign appropriate roles:

2.8 Go-Live Checklist

  • All employees imported with correct pay rates
  • Tax configuration verified (EIN, state IDs, rates)
  • Direct deposit bank info entered for applicable employees
  • Time clock stations created and tested
  • Employee PINs distributed
  • Manager accounts created with correct roles
  • First test payroll run completed and reviewed
  • Accrual balances carried over from previous system
  • Email/SMS notifications configured (SMTP, optionally Twilio)
  • Training sessions completed for managers
  • Employees informed of new system and login methods

2.9 Post-Implementation Support

  • Week 1: Daily check-ins, monitor first punches and time entries
  • Week 2: Review first payroll run, adjust any tax or deduction issues
  • Month 1: Run payroll audit to check for missing data or misconfigurations
  • Ongoing: Monthly audit checks, quarterly tax form generation review

3.2 Company Management

Adding a Company

  1. Go to Companies
  2. Click Add Company
  3. Fill in legal name, DBA, EIN, address
  4. Click Save

Managing Universal Entities

Branches, Departments, Jobs, Positions, Stations, and Employee Titles can be:

  • Company-specific: Assigned to one company only
  • Universal: Leave company field empty to make available to all companies

Divisions, Cost Centers & Secondary Wage Groups

These also support universal assignment. Set companyId to null for enterprise-wide availability.

3.3 Employee Management

Adding an Employee

  1. Go to Employees → Add Employee
  2. Select Company (required)
  3. Enter first name, last name (required)
  4. Set Worker Type: Employee or Contractor
  5. Set Worker Group: hourly_employee, salaried_employee, etc.
  6. Enter Pay Rate and Pay Type (hourly/salary)
  7. Enter hire date
  8. Assign employee number and PIN
  9. Click Save

Employee Profile Tabs

  • Personal: Name, address, SSN, date of birth
  • Employment: Company, department, position, hire date
  • Compensation: Pay rate, pay type, deductions
  • Contacts: Emergency contacts, additional contacts
  • Documents: Upload W-4, I-9, licenses, certifications
  • Direct Deposit: Bank routing/account for ACH payments
Contractor Rule Workers with a contractor worker type or contractor worker group ALWAYS receive zero deductions in payroll. This is automatic and cannot be overridden.

3.4 Time & Attendance

Time Clock (Kiosk Mode)

  1. Navigate to the Time Clock page
  2. Employee enters their Employee Number
  3. Employee enters their 4-digit PIN
  4. System shows current status and options: Clock In, Clock Out, Start Break, End Break
  5. Punch is recorded with timestamp

Reviewing Time Entries

  1. Go to Time & Attendance
  2. Select the date range and company
  3. View all time entries for the period
  4. Approve, edit, or flag entries as needed
  5. Entries show: regular hours, overtime hours, double-time hours

Overtime Calculation

TypeCalifornia Rule
Daily OvertimeHours over 8 in a day = 1.5x
Daily Double-TimeHours over 12 in a day = 2.0x
Weekly OvertimeHours over 40 in a week = 1.5x
7th Consecutive DayFirst 8 hours = 1.5x, over 8 = 2.0x

Time-Off Requests

  1. Employees submit time-off requests from their self-service portal
  2. Managers receive notification
  3. Go to Time & Attendance → Pending Approvals
  4. Approve or deny with optional note
  5. Employee receives email/SMS notification of decision
  6. Approved time off appears as orange overlay on schedule grid

3.5 Scheduling

Creating a Schedule

  1. Go to Schedules
  2. Select the week and company
  3. Click on a cell to add a shift
  4. Set start time, end time, department, and employee
  5. Repeat for all needed shifts

Publishing Schedules

  1. After creating all shifts for the week, click Publish
  2. System checks for conflicts (approved time-off blocks publishing)
  3. If no conflicts, schedule is published
  4. Employees receive email and/or SMS notifications
Important Publishing is blocked (HTTP 409) if any scheduled employee has approved time-off during a shift. Resolve conflicts first.

Recurring Schedules

Set up templates that repeat weekly. Assign employees to recurring shifts to save time.

3.6 Payroll Processing

Running Payroll

  1. Go to Payroll → New Payroll Run
  2. Select company, period start, period end
  3. Set Pay Date
  4. Toggle Direct Deposit (ACH) on/off (default: on)
  5. Click Generate
  6. System calculates for all active workers:
    • Regular pay (hours x rate or salary / periods)
    • Overtime pay (OT hours x rate x 1.5)
    • Double-time pay (DT hours x rate x 2.0)
    • Deductions (Federal, State, FICA, Medicare, custom)
    • Net pay
  7. Review all line items
  8. Click Process to finalize

NACHA ACH Direct Deposit

  1. After processing with direct deposit enabled, a Download ACH File button appears
  2. Click to generate a NACHA-formatted .ach file
  3. Upload this file to your company's bank portal
  4. Bank initiates all direct deposits
  5. Workers without bank info on file are automatically skipped (they receive checks)

Pay Stubs

After a payroll run is processed, pay stubs are generated for each worker. Employees can view their pay stubs in their self-service portal.

3.12 Shift Marketplace

How It Works

  1. Post: Employee posts a shift they cannot work
  2. Browse: Other eligible employees see available shifts
  3. Request: Interested employees request to pick up the shift
  4. Eligibility Check: System verifies:
    • Same company/department/branch
    • No schedule conflicts
    • No approved leave during shift
    • Weekly hours limit not exceeded
    • Minimum rest period maintained
  5. Approve: Manager reviews and approves/denies the request
  6. Reassign: On approval, shift is reassigned to the new worker
Responsibility Policy The original worker keeps responsibility for the shift until a replacement is approved by management.

Marketplace Tabs

  • Available Shifts: Shifts posted by other employees
  • My Posted: Shifts you've posted for pickup
  • My Requests: Shifts you've requested to pick up
  • Approvals: (Managers) Review pending requests
  • Audit Log: Complete history of all marketplace activity
