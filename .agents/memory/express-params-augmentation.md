---
name: Express ParamsDictionary augmentation rules
description: How to correctly augment Express ParamsDictionary for strict TypeScript — required vs optional properties and call-site cast patterns
---

## The Rule
`server/express-params.d.ts` MUST declare all named params (id, workerId, companyId, etc.) as **REQUIRED** (not optional `?`).

**Why:** Making them optional (`id?: string`) causes `string | undefined` errors at 500+ call sites across all parameterized routes, because TypeScript's IRouterMatcher falls back to `P = ParamsDictionary` for all routes, making every `req.params.id` typed as `string | undefined`.

**How to apply:** Keep all named properties as `id: string` (required). This works because TypeScript's overload resolution selects `P = ParamsDictionary` for routes without named params (falling back from `P = {}` when required props break `{}` assignability).

## The Request<{}> Problem

`app.use("/api", (req, res, next) => {...})` lambdas infer `req: Request<{}>` (no path params in the route string). Passing this `req` to helpers typed as `(req: Request<ParamsDictionary>)` fails.

**Fix:** Cast at the call site — `blockDemoWrites(req as Request, res, next)`. Do NOT change the helper signatures to `Request<{}>` — that breaks all parameterized routes by forcing `P = {}` for all handlers.

**Same pattern** applies to `app.use("/{*path}", ...)` (wildcard routes give `Request<Partial<{path: string[]}>>`) in `server/static.ts` and `server/vite.ts`.

## Drizzle json column type mismatch

`remittanceSources.calibrationConfig` is a `json()` column. Drizzle's `$inferInsert` type for the column expects a specific object shape, but `InsertRemittanceSource` (generated by `createInsertSchema`) may have `Json | shape` including plain `string`. 

**Fix:** Cast via unknown: `db.insert(table).values(data as unknown as typeof table.$inferInsert)`.
